Аналитика должна начинаться с вопроса, а не с панели настроек.

Референсы Mobbin подтверждают один устойчивый паттерн: лучшие onboarding-флоу дают один следующий шаг, скрывают второстепенное и постоянно показывают доказательство прогресса. Для Poolstatis это можно усилить агентом: выбрать задачу → скопировать один secret-free запрос → получить серверное доказательство.

Четыре правила «магии»

Это не попытка спрятать сложность. Сложность остаётся в платформе и в доказательствах, но пользователь видит её только в момент, когда она нужна для безопасного решения.

03

Прогресс = server proof

Не «вы скопировали config», а «событие принято, metric активна, query выполнен».

Опасное — только явно

Запуск, env и rollout проходят readiness и человеческое подтверждение.

Onboarding: что делают сильные продукты

Поиск был широким: setup аналитики, подключение SDK или источника и guided progress. Ниже — только то, что действительно видно на найденных экранах.

June
Один раскрытый шаг. Общий checklist виден целиком, но детали показаны только для текущего действия; рядом — docs и demo.
Mixpanel
Copy → verify. В wizard одновременно видны стадия, SDK tabs, один snippet и одна кнопка Verify Connection.
Vercel
Три действия, плюс agent path. Install package, add component, deploy & visit; отдельный блок обещает автоматическую установку агентом.
Cloudflare
Одна форма на один этап. Верхний tracker «hostname → installation → analytics», в текущем шаге только hostname и Done.
Google Analytics
Постоянный этап и статус источника. Пять стадий наверху, data collection в фокусе, один stream и явное «No data received» вместо ложного успеха.

Как это переведено в Poolstatis

Ключевое отличие от обычного wizard: пользователь не обязан руками собирать taxonomy. Агент получает ограниченный запрос, но завершение определяется не его текстовым отчётом, а persisted server evidence.

Experiments: полезные и опасные паттерны

У конкурентов хорошо видны два полюса: безопасный stepper с блокировками и «сырой» экран инфраструктуры. Poolstatis берёт safety-паттерны, но не делает feature flag формой по умолчанию.

Amplitude
Сильный safety stepper. Variants, Goals, Pages, Targeting и blocking warning. Минус — много стадий до первого результата.
Vercel Flags
Variants отдельно от env rules. Production и Preview видны как самостоятельные правила — хороший ориентир для явного scope.
Churnkey
Decision-first список. Active и Finished различаются сразу; для активного доступны Results, Finish и Pause без входа в таблицу настроек.
GitLab
Анти-паттерн для нашего default. Name, description, strategy, type и environments до понимания пользовательской задачи.
Braintrust
Operator settings, не продуктовый workflow. Длинный список toggle подходит внутренней админке, но плохо объясняет цель, rollout и доказательство результата.

Новый контракт экрана Experiments

Пользователь выбирает работу, а не primitive. Под капотом остаются flag, experiment, exposure и metric snapshots, но UI раскрывает их в безопасной последовательности.
